# GURUKUL — AI-first Operating System for Schools

## Stack

Next.js 14 (App Router) · PostgreSQL + Prisma · Tesseract.js OCR (self-hosted assets) · Native credentials auth (bcrypt + JWT session cookies — no third-party auth or email service required)

## Quickstart

```bash
cp .env.example .env        # set DATABASE_URL (PostgreSQL) + AUTH_SECRET
npm install                 # also copies tesseract assets (postinstall)
npx prisma migrate deploy   # create database schema
npx prisma db seed          # demo data + login accounts
npm run dev
```

Seeded logins (change via `SEED_ADMIN_PASSWORD` / `SEED_TEACHER_PASSWORD` env):

| Role | Email | Password |
|---|---|---|
| Admin | `admin@gurukul.edu` | `admin123` |
| Teacher | `turing@gurukul.edu` | `teacher123` |

## Auth & teacher onboarding

- **Login:** email + password (`/login`). Sessions are HTTP-only signed JWT cookies (7 days); all pages & APIs are protected by `middleware.ts`.
- **Adding teachers:** Staff page → **Add Teacher** (admin only) → an **invitation link** is generated (valid 7 days). Share it over any channel — no SMTP/email service needed. The teacher opens the link, sets a password, and is signed in immediately.
- **Timetable:** **Add Slot** button on the Timetable page. Admins schedule any teacher; teachers can only add lectures to their **own** timetable (enforced server-side). Teacher/room/grade clashes and lab requirements are rejected with details.

## Production notes

- Use a managed Postgres (Neon / Supabase / RDS) and set a strong `AUTH_SECRET` (`openssl rand -hex 32`).
- `prisma migrate deploy` runs cleanly on an empty database (baseline migration `0_init`).
- Tesseract OCR assets are served from `/public/tesseract` (no CDN dependency); `worker.min.js` + cores are regenerated by `postinstall`, only `lang/eng.traineddata.gz` is committed.
